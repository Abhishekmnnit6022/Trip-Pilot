# TripPilot — Project Documentation & Architecture
This file documents the complete architecture and features of the AI Travel Planning System (TripPilot). It serves as a guide for future LLMs and developers to understand how the system is built, the features implemented, and how the various agents interact.

## 1. Tech Stack Overview
- **Frontend**: React + Vite (HTML/CSS/JS)
- **Backend**: FastAPI (Python)
- **AI Agent Framework**: LangChain + LangGraph
- **Database & Auth**: Supabase (PostgreSQL)
- **APIs Used**:
  - AviationStack (Flights)
  - RailRadar (Indian Trains)
  - Booking.com via RapidAPI (Hotels)
  - Tavily (Web Search for attractions & train fallbacks)
  - Open-Meteo (Weather Forecasts)
  - Telegram Bot API (Notifications & Interactive Bot)
  - Groq Llama 3 (LLM)

## 2. Completed Phases & Features

### Phase 1: Database & Profiles
- **User Authentication**: Integrated Supabase Auth (Email/Password & Social OAuth).
- **User Profiles Table**: Stores `full_name`, `phone_number`, `birth_date`, `travel_preferences` (jsonb), and `telegram_chat_id`. A trigger auto-creates a profile row on sign-up.
- **Bookings Table**: Stores simulated and actual booking data: `booking_type` (flight/train/hotel), `pnr_or_confirmation_number`, `travel_date`, `details`, and `status`.
- **Backend API (`routes.py`)**: 
  - `GET /api/profile`, `PUT /api/profile`
  - `POST /api/book` (generates PNR and simulates booking)
  - `GET /api/bookings`

### Phase 2: Frontend UI Revamp
- **Profile Modal**: Added a polished modal in React (`ProfileModal.jsx`) allowing users to edit their details and select travel preference tags (Budget, Luxury, Adventure, etc.).
- **Travel Widget**: Built `TravelWidget.jsx`, a quick-search form (From, To, Dates, Travelers) that seamlessly generates a natural language prompt for the LLM.
- **Booking Flow**: Updated `ResultCards.jsx`. External links were replaced with native "Book Now" buttons that hit the `/api/book` endpoint, return a generated PNR, and display a green "Booked" badge.
- **Sidebar Enhancements**: Removed raw debugging data. Added profile and bookings access. Implemented a dynamic "Working..." state to show which AI agent is active.

### Phase 3: Telegram Bot Integration (Full Omnichannel & Multi-Device)
- **Interactive Bot Polling (`telegram_bot.py`)**: The backend runs an `asyncio` background thread using Long Polling (`getUpdates`) to constantly listen for Telegram messages.
- **Secure Multi-Device Linking**: Users can link their accounts from ANY device without needing the phone itself. 
  1. The user sends `/start` to the bot.
  2. The bot asks them to type their registered Phone Number.
  3. A Supabase RPC (`bot_get_profiles`) securely bypasses RLS to verify if the number exists.
  4. If found, the bot asks for their **Date of Birth** (`YYYY-MM-DD`) as a security verification step.
  5. If the DOB matches the database, the account is securely linked!
- **Bot Custom Keyboard**: Once linked, users get a sticky keyboard in Telegram with buttons like "✈️ My Flights", "🚂 My Trains", and "🏨 My Hotels".
- **Database Lookups**: Clicking a button calls a secure Supabase RPC (`bot_get_bookings`) to fetch and display the user's latest PNRs natively inside Telegram.
- **Booking Confirmations**: When a booking is made on the web, a fire-and-forget task in `routes.py` calls `backend.telegram_service.send_booking_confirmation()`.
- **Trip Reminders**: An `asyncio` background loop in `app.py` wakes up every hour, checks for confirmed bookings 24 hours away, and sends a "Pack your bags!" reminder.

### Phase 4: Pro Features (Weather & Packing)
- **Weather Tool**: Built `weather_tool.py` using the free Open-Meteo API. It geocodes the destination city and returns a 7-day forecast.
- **LangGraph Integration (`nodes.py`)**: 
  - The `itinerary_agent` pulls the weather forecast and incorporates it into its day-by-day activity planning.
  - The `final_agent` pulls the weather forecast and generates a highly customized **Packing Checklist** based on the predicted temperatures and rainfall.

## 3. How the LangGraph Pipeline Works
The LangGraph pipeline (`backend/agents/graph.py`) orchestrates the AI logic using a multi-agent routing system:

1. **Router Agent (`router_node`)**: Reads the user prompt and determines what data is needed (flights, trains, hotels, or if it's a general chat).
2. **Data Agents (`flight_agent`, `train_agent`, `hotel_agent`)**: These specialized agents use API tools to fetch structured JSON data. If APIs return no data, they smartly fall back to Tavily web search.
3. **Return Agent (`return_agent`)**: Automatically handles round-trip requests.
4. **Itinerary Agent (`itinerary_agent`)**: Consumes the raw transport/hotel JSON and weather data to generate a detailed day-by-day itinerary.
5. **Final Agent (`final_agent`)**: Takes the itinerary and generates the complete final summary with a customized packing checklist based on the weather forecast.

## Phase 5: Production Hardening & Asynchronous Architecture Fixes
To achieve production stability and handle hundreds of concurrent requests, several major architectural bugs were fixed:
1. **Threadpool Segregation**: Converted synchronous database endpoints in `routes.py` from `async def` to `def`, offloading them to FastAPI's background threadpool.
2. **AI Stream Unblocking**: Replaced `queue.Queue` in `app.py`'s chat SSE stream with `asyncio.Queue`, utilizing `run_coroutine_threadsafe` with an explicitly captured event loop reference. This prevents deadlocking and ensures errors are properly streamed to the frontend.
3. **Zombie Process Eradication**: Switched from `run_in_executor` loops to `daemon=True` threads that auto-terminate with the master process.
4. **Glassmorphism UI**: Applied `backdrop-filter: blur()`, radial gradients, glowing accents, and smooth cubic-bezier transitions across all panels.

## Phase 6: Interactive Booking Wizard & SOS Emergency System
Major UX and safety upgrades:

### 6A. Booking Wizard Modal (`BookingModal.jsx`)
Replaced the old instant-book button with a 3-step wizard:
  - **Step 1 (Review)**: Pre-fills traveler name/phone from the user's profile. Shows trip details (route, dates, provider) in a structured card. Displays a price summary.
  - **Step 2 (Payment)**: Simulated payment gateway with UPI/Card/NetBanking selector. Shows "Processing Payment…" with a realistic 2-second delay.
  - **Step 3 (Confirmed)**: Animated checkmark, large PNR display, and notification summary.

### 6B. Telegram SOS Emergency System (`telegram_bot.py` + `sos_service.py`)
  - **Emergency Contact Management**: Users can set/update their emergency contact (phone number only for speed) via the `📞 Emergency Contact` Telegram button.
  - **SOS Flow**: When user taps `🚨 SOS Emergency`:
    1. Bot sends "Are you OK? Reply YES within 30 seconds."
    2. Bot also displays a button to "📍 Share Location" which generates a Google Maps GPS link using device location.
    3. A `threading.Timer(30)` starts counting down.
    4. If user replies YES → Timer cancelled, SOS aborted.
    5. If 30 seconds pass with no response → `sos_service.send_emergency_sms_free()` auto-sends an SMS containing the user's latest trip details and live GPS link to the emergency contact.
    6. **Fast2SMS Integration**: Because Twilio requires credit card upgrades, we use **Fast2SMS API** to send the emergency SMS instantly (requires ₹100 deposit). The bot auto-formats the number to a 10-digit Indian mobile number.
  - **Database**: `user_profiles` extended with `emergency_contact_phone` (and legacy name column).
  - **RPCs for RLS Bypass**: Because the bot runs on an anonymous key, it uses `bot_get_emergency_contact()` to read and `bot_set_emergency_contact()` to write, securely bypassing Row-Level Security.

## Phase 7: Enterprise Architecture & AI Enhancements
**Goal:** Evolve the prototype into an enterprise-grade, fault-tolerant platform.
- **Circuit Breakers (Fault Tolerance):** Implemented a custom 3-state (CLOSED, OPEN, HALF-OPEN) circuit breaker wrapping all unstable external API tools (AviationStack, RailRadar, OpenMeteo). When APIs fail consistently, the circuit opens and requests gracefully fallback to `TavilyClient` (Web Search) to ensure zero downtime.
- **AI Budget Optimizer (Cyclic Logic):** Shifted the LangGraph pipeline from a simple DAG to a cyclic loop. The AI extracts budget constraints via the `budget_check` node. If a trip goes over budget, the `budget_optimizer` node iteratively swaps flights for trains, downgrades hotels, and recalculates up to 2 times before gracefully proceeding.
- **Stripe FinTech Integration:** Integrated Stripe Test Mode for realistic payment processing. The booking flow now securely creates a `PaymentIntent`, completes a test charge using the `4242` test card, and generates an official Stripe receipt linked to the database transaction.
- **Persistent Chat History:** Created a `chat_sessions` Supabase table synced to the LangGraph Checkpointer (`thread_id`). The UI now features an interactive sidebar that retains past conversations, allowing users to effortlessly resume old AI planning sessions.
- **UX Final Polish:** 
  - Hotel results from Booking.com are locally sorted by price (cheaper first) and rating (best first) for optimal value.
  - The Booking Modal features an interactive Travel Date Picker, allowing users to explicitly lock in their exact travel dates for train bookings before processing Stripe payments.
  - Telegram bot correctly identifies Booking IDs for hotels versus PNRs for transport, parsing detailed JSON blobs for precise information (flight route, check-in dates, etc).

## Phase 8: Itinerary Checklist, Expense Tracking & Dynamic PDF Reports
This phase transforms the bot from a passive booking viewer into an active, on-trip companion.

### 8A. Interactive Itinerary & Expense Checklist
- **Context-Aware Telegram Flow**: When a user selects "🏁 My Trips" in Telegram, they pick a trip. The bot enters a stateful context for that trip.
- **Checklist Logic**: The bot displays the generated day-by-day itinerary as an interactive checklist. As users check off activities, the bot securely logs the corresponding expenses to the `trip_expenses` database table via a dedicated RPC (`bot_add_trip_expense`), circumventing RLS constraints safely.
- **Irreversible Locking**: To prevent duplicate expense logging, once an item is checked off, its callback is replaced with a `noop` (No Operation), graying it out and making it unclickable.

### 8B. Final Trip Completion & PDF Generation
- **Trip Completion Cascade**: When a user clicks "🏁 End This Trip", the `bot_complete_trip` RPC fires. This not only marks the `trips` status as `completed`, but automatically cascades and updates all associated `bookings` to `completed`.
- **Web UI Sync**: The frontend `ChatPage.jsx` sidebar instantly reflects this state, rendering a green `(Completed)` badge next to finished trips.
- **Dynamic PDF Generation**: The backend triggers `_generate_and_send_pdf()` on a background thread. It fetches the trip using a secure `bot_get_trip_by_id` RPC to bypass RLS, then compiles:
  1. The user's original bookings.
  2. The custom expenses logged on-the-go via the checklist.
  3. Formats them into a beautifully styled PDF invoice using `ReportLab`.
- **Bot Delivery**: The completed PDF is instantly sent to the user's Telegram chat via `sendDocument` as a permanent keepsake and expense report.

### 8C. System Hardening & AI Resilience
- **LLM Markdown Parsing Fix**: Updated `nodes.py` and `hotel_tool.py` with custom parsers to strip markdown code fences. This guarantees the backend will not crash when Groq's `llama-3.3-70b-versatile` arbitrarily wraps JSON inside ` ```json ` blocks.
- **Form UI Default Optimization**: Adjusted the Web UI's Travel Widget to default to exactly 1 traveler, improving the baseline user experience.

**Status**: TripPilot is a production-hardened, omnichannel AI Travel Platform with premium UI, secure multi-device Telegram integration, interactive booking flow (Stripe), AI Budget Auto-Optimization, interactive expense tracking, dynamic PDF generation, and an emergency SOS system.

## Phase 9: "Travel Twin" AI Personalization & Observer Agent
**Goal:** Evolve the AI from a static assistant into a continuous learner that adapts travel recommendations based on historical user behavior.

### 9A. Travel Twin Profile & Background Observer
- **Persistent Intelligence (`travel_twin_profile`)**: Extended the `user_profiles` database table with a new JSONB column to permanently store dynamic behavioral metrics (Budget Sensitivity, Hotel Preference Stars, Walking Tolerance, Adventure Preference, Early Mornings, Night Travel, Food Preference) and an array of AI Insights.
- **Asynchronous AI Observer (`twin_agent.py`)**: Developed a dedicated background AI observer. Whenever a user initiates a booking event, a non-blocking background thread captures the transaction data and passes it to the `llama-3.3-70b-versatile` model. 
- **Continuous Learning Loop**: The AI analyzes the booking (e.g., spending ₹45k on a 5-star hotel) and autonomously updates the user's twin profile (e.g., dropping budget sensitivity, increasing hotel stars, adding an insight: *"User is willing to splurge on luxury accommodations"*).
- **Secure RPC Update (`bot_update_travel_twin`)**: Designed custom Supabase RPCs to allow the background background worker to safely read and write twin data by bypassing Row Level Security.

### 9B. LangGraph Context Injection
- **Graph State Integration**: Added the `travel_twin_profile` directly into the LangGraph `TravelState`. The profile is fetched at session initiation and injected as global context across the entire agentic pipeline.
- **Personalized Agent Execution (`nodes.py`)**: 
  - The `hotel_agent` cross-references available properties against the twin's `hotel_preference_stars`.
  - The `itinerary_agent` alters the pacing of its generated day-to-day schedule based on `early_mornings` and `walking_tolerance` parameters.
  - The `final_agent` adds a dedicated `🧠 Travel Twin Personalization` paragraph explaining exactly *why* the AI made those tailored choices.

### 9C. Professional Visualizer Dashboard
- **Profile Modal Overhaul (`ProfileModal.jsx`)**: Rebuilt the frontend User Profile view with a modern tabbed layout.
- **My Travel Twin UI**: Added a dedicated `🧠 My Travel Twin` tab showcasing a premium, glassmorphism dashboard.
- **Visual Analytics**: The dashboard maps the raw JSON data to interactive progress bars (for Budget and Star Ratings) and neatly styled stat grids (for Adventure and Walking limits), alongside a live feed of AI Insights.

### 9D. Telegram Smart Itinerary Enhancements
- **Free/Paid Activity Mix**: Modified the Telegram bot's itinerary LLM prompt to intentionally generate a mix of paid and free local activities, setting `estimated_cost` to `0` for free items.
- **Smart Expense Routing (`bot_trip_features.py`)**: When users check off an itinerary item in Telegram, the system intelligently checks the cost. If it's a paid activity, it executes the expense logging RPC. If it's free, it simply checks it off without artificially inflating the trip's expense report with zero-value line items.
